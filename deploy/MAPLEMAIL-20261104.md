# MapleMail 更新说明（2026-11-04）

## 2026-11-05 补充：导入前完整验证、发送提速和客户删除

本节替代后文早期的发送前校验及“暂存待验证后可发信”行为。用户已确认：关键词命中与明确无效地址在导入时自动排除；DNS/MX、SMTP、Catch-all 均在导入预览期间执行。只导入验证通过的联系人；待确认地址不进入分组，可下载 XLSX 待处理表。验证可选择已授权发件箱，默认选择可用邮箱；后台共享队列持续处理，翻页、切换筛选不重启探测。

发送阶段不再进行有效性探测，仍检查权限、退订、黑名单、频率、预热与实际 SMTP 返回结果。历史 validation_hold 记录不会自动释放；管理员明确确认后可加入发送队列，暂停任务仍保持暂停，unknown 发送结果不会自动重发。

统一 Message-ID 有无尖括号的关联，准确关联主收件人退信和送达；抄送与旧重试不会重复计数。任务列表增加“对方服务器已接收”，其含义不等同于进入收件箱。发件人通用策略 scope_key=* 作为各发件人的默认策略，精确策略优先。

CRM 增加 crm:delete 权限、列表及详情删除操作、确认提示和审计。删除采用保留历史的方式，客户从列表移除，消息、跟进和邮箱原始信件保留；删除后不能查看或回复该客户，自动同步不会重新显示，重新添加同一邮箱可恢复。

每台服务器独立备份数据库和配置后发布；保留既有邮箱凭据与任务暂停状态。按各自邮箱域名持久配置 Postfix myhostname/smtp_helo_name 并重载。未配置 SMTP 中继，Gmail 对发送 IP 的外部拒绝不能保证仅通过本次代码改动解除。

应用数据库连接池调整为最多 32 个连接、8 个空闲连接、连接寿命 5 分钟，为 Postfix、Dovecot 和 Webmail 留出数据库连接余量。连接池补丁发布时暂时锁定新任务领取，等待在途 SMTP 完成后更新应用，不修改任务暂停开关；核对期间用户新增的邮箱和任务控制操作均保留。

## 2026-11-05 补充：导入待验证筛选与大表验证

补齐 Excel 预览 API 对 pending 状态的请求校验。DNS 按域名去重，批量读取持久缓存；大表查询使用共享的 16 个后台工作线程，切换筛选、分页或请求超时不会中断已排队的查询，后续预览累计读取结果。修复 PostgreSQL 验证缓存写入错误；网络异常后前端继续刷新待验证结果。系统 DNS 临时失败时使用 HTTPS DNS 备用查询，明确不存在、Null MX、私网地址和无法确认的结果仍按原验证规则处理，不绕过 SMTP/Catch-all 检查。

确实无法确认的 DNS 地址默认阻止导入。新增显式选项“暂存待验证邮箱”：需要有效预览凭据和用户勾选，保留这些联系人而不把它们标记为验证通过；发送前仍严格验证，未确认时进入暂缓发送记录并显示原因。适用于添加分组和向现有分组导入，不影响无效行必须单独确认跳过的规则。

## 2026-11-05 补充：实时发送统计与严格邮箱验证

营销任务表格设置明确列宽与横向滚动，操作列固定在右侧；新增统计字段后，暂停、分析、复制、删除等按钮仍可直接查看和点击。

营销任务列表每三秒刷新当前页，隐藏页面停止请求。成功、失败、跳过、待确认和进度从当前收件人记录汇总，独立核对最新收件人投递日志；抄送、重试、延迟记录不重复计数，不再把 98% 提前显示为 100%。成功表示已被 SMTP 接受且没有记录退信，实际入箱仍取决于对方邮件系统。

XLSX 预览和导入校验 DNS/MX、Null MX、收信主机公网地址及合法的隐式 MX。网络查询暂时失败保留为“待验证”，不会自动丢弃或加入永久黑名单；预览自动重试，验证结果变化会使旧预览确认失效。

按用户选择采用严格模式：系统内 Go 发信服务（营销任务、发信 API、客户回复等）发送前检查收信地址。SMTP 验证使用 MAIL/RCPT 和随机地址对照，不发送 DATA 或正文；识别明确不存在、临时拒绝、策略限制、邮箱已满及 Catch-all。通配接收与其他无法确认结果进入 `validation_hold`，不自动发信。“重新验证”只重新加入验证队列，不绕过验证，也不重发发送结果不明的记录。暂停任务需恢复后才能处理队列。对本服务器管理的域名采用实时邮箱/别名数据作为权威依据。

DNS、SMTP 和通配检测结果持久化缓存；通配域不会反复逐地址探测。网络连接限流、限制超时，拒绝私网及云元数据地址，连接已校验的公网 IP 避免 DNS 重绑定。原有异常邮箱扫描使用相同规则，临时失败和无法确认不执行删除/拉黑操作。

本次仅增量增加验证缓存表及收件人验证字段、索引。部署前分别备份两台数据库，保留原账号、邮箱、联系人和任务，不导入或覆盖另一台服务器数据。

## 2026-11-05 补充：部门营销工作台名称显示

工作台所有标签页及批次、自动化进度明细改为显示关联名称：部门、上级部门、角色、分组、模板、操作人、任务名称和联系人邮箱。原 ID 保留在接口和编辑数据中，不再作为列表展示内容；统计数量保留数字。状态、发送周期、权限、发送策略改为本地化描述，支持中文、英文和日文。

后端只批量解析当前页涉及的关联记录，并按关联资源的查看权限和数据范围过滤，避免跨部门名称泄露；不依赖下拉框首屏缓存，因此大分组列表和分页后的记录也能正确显示。不存在或不可见的关联显示文字提示。刷新后读取最新名称，无需更改数据库结构。

已增加真实 PostgreSQL 回归，覆盖关联超过 200 条、分页、名称修改、原 ID 保留和跨部门过滤；前端回归覆盖关联名称、权限、周期、状态和策略描述。华为云、阿里云分别备份后更新应用容器，保留各自数据库、账号和业务配置。

- 部门工作台先预览有效、无效及过滤行数，支持下载无效行、仅导入有效行。已存在邮箱跳过，不修改其密码。邮箱密码空白使用用户指定的默认值。

## 营销任务与 API

- 营销任务支持多个发件箱、多个收件分组及多个标签；相同邮箱跨分组只发送一次。发件箱按收件人顺序轮换，重试保留原分配；API 使用数据库原子游标轮换。
- 每个发件箱和分组都执行部门权限检查，所有发件箱继续遵守频率、间隔和额度限制。
- 营销任务、API 可选填一个抄送邮箱。每封邮件均向其发送副本，会增加实际邮件量。含抄送时关闭该任务/API 的个人打开和点击跟踪，避免将抄送对象的行为算到主收件人。
- 多标签可使用 AND / OR / NOT。跨所选分组按邮箱合并标签条件。

## CRM

- 新增 CRM 导航、客户搜索、询盘/报价/谈判/成交等阶段、公司和国家、跟进日期、跟进记录及邮件往来。
- 选择已授权邮箱，点击同步读取收件箱。首次最多读取最近 100 个 UID，后续每次最多增量读取 100 个 UID；需要时重复点击同步。同步不删除或移动原邮件。收件箱中普通来信也会作为客户记录，业务人员可以再标注阶段。
- 打开来信查看正文，在详情内回复。回复沿用实际接收邮箱及邮件线程头，执行部门授权和发送限额，并以请求 ID 防止重复发送。发送结果不明确时显示待核对状态，不自动重复投递。
- CRM 权限：`crm:list`、`crm:manage`、`crm:sync`、`crm:reply`，管理员可以在部门角色中分配。
