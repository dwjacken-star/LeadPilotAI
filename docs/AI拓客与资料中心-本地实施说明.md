# MapleMail 资料中心与 AI 拓客

本次在现有 Go 服务、Vue 管理台、PostgreSQL 和权限体系内增加功能，不增加独立后台。开发阶段先完成本地实现与测试；之后按新增指令更新了阿里云并切换为 best-maple.com 单域名，详见同目录《阿里云更新验收-20261106.md》。没有更新华为云，没有调用付费 AI，也没有为验收新增真实营销邮件。

## 功能入口

### 资料中心 `/materials`

- 公司：维护名称、品牌、域名和业务事实，保存内部草稿，单独发布对外可用资料。管理员可向指定部门共享资料。
- 产品：维护 SKU、名称、分类、OE 和其他业务参数；产品单独审核发布，未发布产品不参与自动开发信。
- 导入：产品 XLSX 遍历全部工作表和数据行，保留文本编码与前导零。标准中英文表头直接映射；不明确的表头可用 AI 或人工列映射。最多 100,000 数据行，不依赖模型读取 Excel 的行数限制。
- 保护：人工编辑过的字段不会被后续自动导入覆盖；已有值冲突、缺失 SKU 或名称等保留为待复核行。支持分页预览、人工确认、待复核 XLSX 下载及产品导出。
- 图片：上传 ZIP 或单张 JPG/PNG/WebP，支持 XLSX 内嵌图片提取。按表格图片路径、图片锚点、SKU 文件名明确匹配；存在歧义时保留候选，支持人工关联及主图、侧面、标签、包装、尺寸角色。管理台提供缩略预览。
- 公司资料：支持 PDF、DOCX、PPTX、XLSX、TXT/MD、图片。Office 文件本地提取文本和内嵌图片，再调用 AI 分类和提取事实、证据与位置。识别结果可合并到公司草稿，避免自动覆盖人工资料。
- 每个上传文件不超过 128MB；ZIP 不超过 5,000 项、展开不超过 512MB、单项不超过 32MB，禁止路径穿越和符号链接。图片不超过 4,000 万像素；大 PDF 识别前需要拆分（当前单次 PDF 输入上限 20MB）。
- 原文件保存在私有目录。下载、缩略图、版本记录均经权限校验；共享部门只能读取已发布产品及明确设为公开、已发布的资料。上传没有复用第三方公开图床。

### AI 智能拓客 `/outreach`

1. 选择公司和已发布产品，填写目标客户要求、国家 ISO 两字母代码、语言代码及目标市场时区。
2. 设置每日执行时间、每日新增线索和发信上限、搜索词和站点数量、邮箱过滤关键词、发件箱池、发送时段、间隔和客户冷却天数。
3. 模型生成指定市场的搜索词，联网搜索取得网站来源，服务端访问公开网页及联系页提取**实际出现的邮箱**。不使用模型猜测的邮箱。
4. 每条线索保留网站、国家、语言、公司摘要及来源证据。国家和客户匹配证据不足的记录进入人工复核。
5. 采集后复用 DNS/MX、SMTP 和 Catch-all 验证。关键词命中地址不进入线索；明确无效地址不进入开发信；超时、Catch-all 等无法确认结果保留在线索列表及导出中。
6. 只向验证通过且仍在有效期内的线索生成按客户语言编写的开发信。内容引用已发布资料，并冻结公司、产品、素材版本及客户来源快照。
7. 关闭自动发送时，开发信等待有发布权限的人员确认；开启时，按计划进入现有邮件发送引擎。验证时记录探测使用的发件箱；验证通过并实际入队时使用计划持久化游标轮换发件箱，无效和待确认地址不会消耗发送轮换位。保留现有发件箱授权和 SMTP 策略。SMTP 验证确认的是地址可接受性，不代表不同发信身份的最终投递信誉相同。
8. 每封个性化信件使用单个收件人的现有营销任务，同时通过共享计划限额控制跨任务的实际发送间隔、并发和每日额度。各市场发送时段也写入现有发送策略，限速后延期的邮件仍遵守时段。
9. 超过当日入队限额会安排下一天继续；跨计划客户冷却命中时取消当前重复候选并显示原因。退订、权限撤销、资料变更、计划暂停或客户回信会在 SMTP 交接前阻止发送。发送引擎不再做 DNS/SMTP 网络验证。
10. 未发送内容失效后可“重新生成开发信”：保留旧快照、取消尚未交接 SMTP 的旧任务，创建新版本执行记录并重新验证与生成。已发送、不确定或已进入交接阶段的邮件禁止重新生成，避免重复发送。

计划按每日规则运行；一次错过多个调度周期时补一个执行记录，不集中补发全部历史日期。计划修改后默认暂停，需重新启用。后台任务持久化、有限并发，具有租约、失败重试、取消和待配置状态。

### 询盘与客户管理

- 在“收件与转发设置”中选择授权邮箱、所属公司和可选的真实询盘转发地址，启用后自动同步 INBOX。
- 自动回复先按邮件头及明确规则排除；其他来信由 AI 辅助分类。分类不明确的内容等待人工确认，不自动当成询盘转发。
- 人工确认或高置信度真实询盘进入现有客户管理；点击可打开对应客户与邮件，继续记录跟进。
- 退订会停止对应线索并取消同部门联系人订阅。疑似人工回信在分类期间暂停后续自动开发；识别为人工回信后停止继续开发。
- 真实询盘可转发到预设地址，并附带 `original.eml`，保留原始 MIME 和附件；使用唯一转发记录和邮件标记防止重复与循环。交接结果不确定时保留 `unknown`，需人工核查，不自动重发。
- 客户管理可选择公司资料“AI 起草回复”，查看需人工补充的事实，编辑后使用原有人工确认发送操作。AI 不会直接发送客户回复。
- 沿用现有 INBOX 同步游标和权限；初次同步采用现有模块最近 100 封邮件的起始范围，后续增量同步。历史全量回填及其他文件夹不是本次新增功能。

## 首次使用配置

1. 管理员进入“AI 服务设置”：填写兼容 OpenAI **Responses API** 的 HTTPS 基础地址、模型、API 密钥。模型需支持结构化输出；PDF/图片识别需要相应视觉能力；联网搜索需要 `web_search` 支持。仅兼容 Chat Completions 的服务不能直接用于本模块。
2. 设置每日调用次数、Token 预算和单次输出上限。预算包含失败请求的保守预留，避免无限重试；文件较大时可能需要拆分或调整预算。接口返回用量后更新实际统计。
3. 密钥在数据库内加密，不回显；加密主密钥存放在私有资料目录 `.ai-master-key`。**数据库与该目录必须一起备份和恢复**。密钥留空保存时保留原值。
4. 开启相关账号的功能权限及发件箱授权，确认现有 SMTP 服务与发信域名设置可用，再启用计划及收件规则。
5. 先上传与发布少量准确的公司、产品资料，关闭自动发送跑一轮，核对真实来源、邮箱验证及生成内容后，再按业务需要开启自动发送。
6. 缺少配置、调用额度或外部服务能力时，任务保留具体原因；补齐后从后台任务列表重试。不会伪造完成结果。

建议权限组合（沿用现有角色的数据范围，不默认给普通账号扩权）：

| 职责 | 权限 |
| --- | --- |
| 资料维护 | `company:list/manage`、`material:list/upload/recognize/manage/download`、`product:list/import/manage/export` |
| 资料审核 | 上述读取权限以及 `company:publish`、`material:publish`、`product:publish` |
| 拓客操作 | `company:list`、`product:list`、`material:list`、`outreach:list/manage/run/export`，以及相关发件箱授权 |
| 自动/审核发信 | 在拓客操作权限基础上增加 `outreach:publish`、`campaign:create/publish`、`contact:create/list`、`template:create/list` |
| 询盘处理 | `company:list`、`product:list`、`inquiry:list/manage`、`crm:list/sync/manage/reply`、`crm:ai_draft` 及对应邮箱授权 |

资料删除使用归档；历史快照保留。公司跨部门共享与 AI 服务密钥设置仅管理员操作。

## 数据与后续发布边界

- 新增 `bm_growth_*` 表；已有 `recipient_info` 和 CRM 邮件表只增加关联、同步元数据字段。
- 迁移位于 `core/internal/service/governance/growth.sql`，通过现有启动迁移执行，可重复执行；没有删除原数据库或历史邮件的语句。
- 私有目录默认 `core/data/growth-files`，可用 `MAPLEMAIL_GROWTH_DATA` 覆盖。现有 Compose 已挂载 `core-data` 到服务的 `core/data`，默认路径属于该持久化卷。
- 构建入口仍为 `core/main.go`。仓库中另有 `run_dev.go` 的独立 `main`，因此使用 `go build ... main.go`，不使用 `go build ./`。
- 本地候选构建保存在 `.tools/maplemail-growth-local`，阿里云正式构建在 `.tools/maplemail-growth-ali`，前端构建在 `core/frontend/dist`。旧版本二进制仍保留；阿里云部署使用了独立构建与备份。
- 此后发布仍应先备份 PostgreSQL、配置、邮件数据、Postfix 队列及 `core-data`，同时发布后端和前端文件，再检查迁移、权限、私有目录和任务状态。本次阿里云已按此流程执行。

## 本地验证范围

自动化测试覆盖：3,000 行多工作表入库、前导零保留、重复导入、人工字段保护、SKU 图片关联、ZIP 路径检查、部门隔离及共享撤销、真实 GoFrame HTTP 上传/下载与权限边界、模拟搜索采集和验证、冻结开发信及版本失效、旧版本保留与重新生成、询盘分类与转发去重、人工回复草稿、密钥加密、Responses 请求格式及预算、已有发件箱池与 SMTP 富文本回归。模拟 SMTP 只在本机接收测试载荷。

前端执行构建、现有修复测试、工作台数据规范化测试、新菜单权限测试和中英日语言一致性检查。随后完成阿里云 HTTPS、静态入口文件、授权接口、SMTP/IMAP/POP3 TLS、单域名配置和数据保留检查。真实付费搜索、真实客户邮箱投递/收件及浏览器人工页面验收尚未进行。

主要实现位置：

- `core/internal/service/growth/`：资料、识别、搜索、验证、开发信、调度、询盘。
- `core/internal/service/outreachguard/`：SMTP 前的冻结内容与可发送状态检查、共享计划限额。
- `core/internal/controller/growth/`：受现有登录与部门权限保护的 API。
- `core/frontend/src/views/growth/`：资料中心与 AI 拓客页面。
- `core/frontend/src/views/crm/index.vue`：AI 回复草稿及询盘跳转。

接口参考：[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)、[File inputs](https://developers.openai.com/api/docs/guides/file-inputs)、[Web search](https://developers.openai.com/api/docs/guides/tools-web-search)。
