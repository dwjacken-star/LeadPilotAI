# 行业通用 Growth Master 交付与验收

入口：现有管理台中的「全球情报与智能获客」，页面路径 `/intelligence`。

本版本沿用 Go/GoFrame、Vue、PostgreSQL 与 Redis。没有新增独立管理后台，也没有接入 Postiz。

## 已实现

- 一个逻辑总控先生成受目标市场、工作流与预算约束的策略，再调用十四个专业业务 Skill；每个 Skill 有独立模型、启停、超时、重试、处理数量和输出上限配置。
- 六条持久化工作流：行业日报、采购需求、客户发现、内容与渠道执行、回复询盘、效果分析。支持立即执行、日/周/六小时/事件触发、暂停、取消、恢复、租约恢复和节点结果追踪。
- 通用、汽车配件、企业服务三个基础行业模板，支持复制、动态字段类型、必填/枚举、关键词、来源域名、评分规则、置信度与版本快照。
- 行业动态 XLSX 模板、上传预览、错误数据下载、只导入有效新行；保留 SKU 前导零，导入资料保持未发布状态，重复确认不会重复写入。
- Serper 搜索与网页采集、来源缓存与证据引用、公开邮箱提取、过滤、DNS/MX/SMTP/Catch-all 核验；低置信度、无效或待确认地址不自动进入触达集合。候选客户可下载核验表。
- 可解释评分、只匹配已发布的产品/服务、关联既有客户管理，保留既有客户阶段、备注与删除状态。
- 多语言邮件与社媒正文、富文本预览、已发布公司图片选择、具体版本审核、记录联系依据、原生邮件/社媒队列及回执同步。发信阶段不重复进行邮箱网络核验。
- WhatsApp Business 官方 Cloud API 模板映射、实际模板内容预览、加密凭证、HMAC 回调校验、回调去重、状态回执与立即退订阻断。配置完成前保持禁用。
- 邮箱询盘事件与客户跟进、人工回复草稿。可单独启用经授权审核的精确 FAQ 固定邮件答复；报价、账期、质保、合同、模糊问题与其他渠道继续交人工审核。
- 工作流预算、供应商全局预算、费用单价配置、全局暂停、部门权限、实际发送前授权/审批/资料/回复状态校验和审计。
- 执行统计展示实际数据与时间；SMTP 受理不视为收件箱送达，没有真实收入/成本归因时 ROI 留空。

## 本地验收证据

后端独立 PostgreSQL 回归通过：growth、social、growth controller、governance、contactimport、emailvalidation、crm、batch_mail。

新增端到端业务用例包括六条工作流、不同产业字段、来源缓存、SMTP 与 Catch-all 隔离、关键词过滤、评分匹配、CRM 关联、待审核暂停、原生邮件入队、发送时不重复验证、权限撤回、部门隔离、并发去重、预算阻断、XLSX 预览与幂等确认、FAQ 固定答复、原生社媒发布与回执、WhatsApp 模板与签名回调。

外部搜索、模型、SMTP、社媒和 WhatsApp 在本地业务用例中使用受控模拟接口；未通过这些用例向真实客户发信或在真实主页发布。

前端 20 项检查通过；2544 个中英日语言键与插值一致，生产构建通过。保留项目已有的非阻断 lint 警告。

浏览器自动化运行工具在本轮不可用，因此不把构建和 API 验收描述为浏览器视觉验收。

## 使用顺序

1. 选择公司，复制并配置行业包。
2. 在资料中心上传公司、产品或服务资料及图片；检查并发布可用于对外沟通的资料。
3. 配置技能模型和预算，建立目标市场工作流；新建工作流默认不启动定时执行。
4. 执行发现流程，查看证据、过滤及核验原因，为允许触达的客户记录联系依据。
5. 运行内容流程，审核具体内容和对象后交给既有发送/发布队列。
6. 选择既有收件规则启用询盘事件流程，查看草稿和客户跟进。精确 FAQ 自动答复须另行开启并审核。

现有营销和拓客计划不自动迁入新工作流。Facebook、LinkedIn、WhatsApp 是否可正式使用，取决于各自实际授权、接口能力及配置；接口代码存在不等于账号已获得权限。

WhatsApp 官方依据：
- https://developers.facebook.com/documentation/business-messaging/whatsapp/reference/whatsapp-business-phone-number/message-api
- https://developers.facebook.com/documentation/business-messaging/whatsapp/templates/overview
- https://developers.facebook.com/documentation/business-messaging/whatsapp/webhooks/create-webhook-endpoint/

## 发布与回退

发布前备份 PostgreSQL 和原应用配置，只替换 MapleMail 应用及静态资源，沿用现有数据卷、账号、证书、域名、邮件服务和同机其他应用。

新增数据库结构采用追加迁移。回退应用前先暂停新工作流以及带 `master_content_id` 的邮件/社媒任务；保留数据库和邮箱，不通过恢复旧数据库覆盖上线后的业务数据。

实际发布镜像、备份目录、文件校验和和线上验收结果写入服务器 `deploy/MAPLEMAIL-GROWTH-MASTER-20261110.json`。
