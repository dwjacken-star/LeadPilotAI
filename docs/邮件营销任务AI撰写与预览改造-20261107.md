# 邮件营销任务：模板与 AI 撰写

## 使用入口

现有「邮件营销 → 添加任务 / 编辑任务」。左侧选择模板或 AI 撰写，设置国家、语言、模型、写信要求、发件箱与收件范围；右侧编辑显示名称、主题和正文，并查看桌面、手机富文本预览。模板支持直接编辑 HTML；AI 正文还可切换富文本编辑器。

AI 支持一次生成名称、主题、正文，或只调整一个字段。已有内容被替换前显示生成结果，不合适可保留现有内容。AI 请求失败、超额、返回内容不合要求时，不覆盖草稿。生成不会新建发送任务、写入模板库或发信；实际发送仍由用户确认任务和时间。

## 数据与发送

- 内容快照保存在既有 `email_tasks.snapshot_content`。修改模板任务、AI 正文、重新选择模板均保存本次正文，不修改模板库。
- 模板模式依旧检查所选模板的部门读取权限；AI 独立正文允许 template_id 为 0。正文上限 1 MB。
- 增量增加 `email_tasks.authoring_config JSONB NOT NULL DEFAULT '{}'`，记录来源、国家、语言、模型、要求。旧任务不变，不删除任何数据。
- 编辑任务加载已保存快照；任务详情、测试发送、正式发送使用相同正文。进行中的任务必须暂停后编辑；事务内锁定记录再次校验。
- 正式发送保留发件箱轮换、退订拦截、跟踪、抄送与 IP 预热既有规则。未进行任何客户群发作为验收。

## AI 服务与权限

复用现有智能拓客 AI 服务设置、加密密钥和全局每日调用/token 限额。`campaign_options` 仅返回启用状态、默认模型和模型列表，不返回密钥或允许部门用户改变服务地址。`campaign_compose` 要求现有 `campaign:create` 权限；非默认模型须来自已配置提供商模型列表，单次输出最多 4000 tokens（若原配置更低则遵循原限制）。每次实际生成计入 `bm_growth_usage`，记录实际所选模型和提供商 token 用量。

AI 返回受约束的纯文本段落、显示名称、主题和语言。服务器检查语言、长度、空字段和邮件头换行，转义正文并生成带段距、换行和语言方向的 HTML。系统不要求模型生成可执行 HTML 或实际退订地址。

## 验证

本地独立 PostgreSQL 集成用例覆盖无模板正文创建、快照回显、模板不被修改、编辑事务、发送中禁止编辑、越权阻断、参数开关持久化，以及模拟 SMTP 收到的段落格式、显示名称、退订和跟踪。AI 测试用固定 HTTP 响应验证模型切换、结构化结果、转义、用量记账和预算阻断。前端验证包含三语言键一致性、既有拓客回归、构建和实际浏览器操作；线上生成与部署验收结果另存发布记录。
