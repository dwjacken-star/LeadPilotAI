# 拓客资料显示与搜索数量

候选公司和客户线索详情在完成原有部门/归属权限校验后，补齐所属公司、计划、执行和关联收件人/营销任务的名称。显示不依赖公司下拉框的权限或分页。国家、语言、布尔值、时间、验证结果和常见处理原因转为界面语言；主要详情采用业务字段清单，原始采集 JSON 收在折叠项中。

候选公司列表在电话前展示邮箱，超过两个地址可进入详情查看全部。详情显示每个已采集地址的过滤、验证或待处理状态及原因，已有对应线索可以直接查看。保留未通过验证和被过滤的地址供核对；只有原有验证及发送规则通过才会发信。打开候选公司、线索或执行详情时每五秒刷新，采集过程中也能查看新增邮箱。

列表增加“查看已采集邮箱”快捷筛选，按服务器数据筛选全部分页，并支持在搜索框输入邮箱查找公司。筛选值作为查询条件处理，保持下拉框可选值与后端一致。

地图地址中的经纬度和 URL 片段可能被宽松邮箱解析器识别成地址。后续公开邮箱采集排除此类数字域名及明显 URL 片段；历史记录不删除，显示为格式无效。DNS/MX 通过单独显示为待 SMTP 验证，不冒充完整邮箱验证通过。

当前两条计划按每个目标国家一组关键词、每组至多三个网页搜索结果、每家公司至多三页设置，使用网页搜索渠道。两国家计划单次最多约六条站点结果、十八页抓取；三国家计划最多约九条站点结果、二十七页抓取，实际会因去重或无联系页减少。只修改搜索规模和渠道，保留发送身份、频率、日发送上限、时间、启用状态和历史执行快照。不增加每日 AI 预算、不清空用量记录，不自动重跑营销。

只有未运行后台任务的计划才应用配置调整。关键词生成校验在数量允许时覆盖各目标国家并均匀分配；新建计划按市场数量提供保守初始值。验证包括纯显示逻辑、隔离数据库关联名与邮箱状态、采集格式与完整拓客回归，线上以真实已采集资料只读检查。
